# code-film: 3D films written as programs

The film is a program that answers one question: **what does the screen look like at time t?**
Nothing is generated by a video model and nothing is animated by hand. Fixes are cheap:
change one number in `timeline.py`, re-run, only the affected frames re-render.

```
timeline.py ──► ui.html ──(Playwright, per frame)──► ui/f_####.png ─┐   layout.json (measured rects)
     │                                                              ▼          │
     ├──────────────► scene.py (bpy: slabs, character, camera, keys) ◄─────────┘
     │                    └─(render.py, Cycles)──► frames/<q>/f_####.png ─┐
     ├──────────────► sound.py (numpy/scipy/pedalboard) ──► sound.wav ────┤
     └──────────────► check.py (QA: sheets, framing, pops, audio sync) ◄──┘──► ffmpeg ──► film_<q>.mp4
```

## Start a film

```bash
bash .claude/skills/code-film/scripts/setup.sh            # once per machine: venv with bpy etc.
bash .claude/skills/code-film/scripts/new_film.sh films/my-film
PY=/opt/b3d/bin/python films/my-film/film.sh preview       # ~1-2 min on 4 CPU cores
```

The template is a working 9 s film (character hops across Type/Rect/Pen/Glow/Play buttons,
each press builds a title card, Play rides the playhead, panels power down and fall away,
the finished card remains). Adapt it rather than starting blank.

## Workflow (follow in order, never skip the loop)

1. **Brief → beat sheet.** Write the story as events on beats (BPM 120 → 1 beat = 0.5 s).
   Every landing/hit on a beat. 8–12 s is the sweet spot; longer costs linear render time.
2. **timeline.py**: FPS, BPM, DURATION, PANELS, HOPS `(takeoff_beat, land_beat, target)`,
   event beats. Targets are *names*, never coordinates.
3. **ui.html**: the 2D world. Every landing target is `[data-btn]`/`[data-spot]`, every 3D slab
   a `[data-panel]`. `render(t)` must be a pure function of t (rules below).
   Check a few UI frames by eye (`render_ui.py --every 30`, then Read `ui/f_0151.png`).
4. **scene.py**: change character/lights/camera offsets if needed. Leave the measured-layout,
   per-frame baking and fall logic alone unless the story needs it.
5. **Preview loop** (`film.sh preview`) — repeat until it passes, typically 3–6 rounds:
   - `check.py` must print zero `FAIL:` lines.
   - Read `qa/preview_sheet.jpg` AND `qa/preview_landings.jpg` every round. Judge:
     character readable and in frame, button press visible at each landing, no blown
     highlights, background not a flat wall, final frame composed, title legible.
   - Fix the cause in timeline/scene/ui, never by hand-editing frames.
6. **Draft** (`film.sh draft`, 960×540 all frames). Check the sheet again, then look at
   2–3 full-size frames around the riskiest moment (biggest hop, panel fall).
7. **Final** (`film.sh final`, 1080p, 96 spp) only after the draft passes. Re-render a
   bad range with `render.py final --frames 120-150 --force`.
8. Deliver `film_<q>.mp4` plus the contact sheet; say what was checked and what wasn't
   (you cannot listen to audio — say the sync was verified numerically).

## Rules that make it work (each one was a real failure)

**Single source of truth**
- Positions are *measured*: `render_ui.py` calls `layout()` (getBoundingClientRect) →
  `layout.json` → `scene.py` maps px→metres (`px2w`). Never type a button position into Python.
- Times in beats (`b(x)`), so music, SFX and motion share one grid by construction.
- `render_ui.py` aborts if timeline.py names a target/panel that ui.html lacks.

**ui.html**
- No CSS transitions/animations, timers, `Date.now()`, `Math.random()`. A frame must be
  reproducible on its own, out of order, in any process. `* { transition:none!important }`.
- Local fonts only (headless render has no network). Canvas for anything drawn (the comp).
- Inject data with `add_init_script("window.TL = ...")` before page scripts run.

**Blender (bpy)**
- No GPU → **Cycles CPU + OIDN denoise**. EEVEE on software GL was ~8× slower (50 s vs 6 s/frame)
  and needs libEGL. `setup_gpu()` picks OPTIX/CUDA/HIP/METAL when present.
- `render.use_persistent_data = True`; render frame-by-frame in one process, swapping the UI
  texture with `img.filepath = ...; img.reload()` before each frame.
- Bake animation as one key per frame from a pure function `at(t)`, not hand-tuned Bezier keys.
  Physics-ish hop: linear-ish horizontal, parabola vertical, anticipation squash (0.12 s),
  air stretch ∝ vertical speed, landing = damped cosine squash, volume preserved (sxy = 1/√sz).
- Keep squash/stretch on a root whose origin is at the feet; put static size on a child `rig`.
- Flicker/power-down keys must be CONSTANT: set `preferences.edit.keyframe_new_interpolation_type`
  before inserting (fcurve APIs differ between 4.x and 5.x layered actions).
- Area lights on a glossy/coated screen show as hard white rectangles: `light_obj.visible_glossy = False`.
- UI slab = bmesh quad with UVs cropped to its rect + Solidify (rim material offset) + small bevel.
  Inset each panel a few px so seams read as separate physical slabs.
- World gradient: TexCoord.Generated → SeparateXYZ.Z → ColorRamp; keep it dark (#2c170b → #050302)
  or it reads as a flat orange wall.
- Camera: smoothed (exp, ~0.3 s) follow of a 0.25 s look-ahead point, partial height follow (0.6×z),
  ease-in-out push for the intro (≥2 s) and the end move. DOF focus on an empty that tracks the subject.
- Cap hop apex (`HOP_MAX_H`) and give long hops ≥ 1 beat, or the subject leaves frame / smears.

**Sound**
- Synthesize: kick = sine with exp pitch drop; snare = band noise + 185 Hz tone; hats = HP noise;
  keys = sine + 2nd harmonic + tremolo; glock = inharmonic partials (1, 2.76, 5.4).
  SFX from the same HOPS: boing at takeoff, glass knock at landing, glock note per press (pentatonic up).
- Fixed RNG seed. Write exactly `DURATION` seconds. Drums drop out at the power-down.

**ffmpeg**
- Always `-pix_fmt yuv420p` (PNG input otherwise becomes yuv444 and won't play on phones/QuickTime/browsers),
  `-movflags +faststart`, `-crf 17`, `-shortest`.

**Iteration hygiene**
- Frames are resumable (existing frames skipped). `.stamp` holds a hash of the sources; if
  timeline/scene/ui changed, old frames are deleted automatically, so stale frames cannot leak into
  the film. `--frames a-b` patches a range without wiping.
- `check.py` thresholds: character inside 3–97 % of frame, ≤ 12 % of frame width per frame,
  camera accel ≤ 0.01 m/frame², landing knock within 1 frame of the landing, no black/blown frames.

## Time budget (4-core CPU, no GPU; scale by ~20–50× faster on an RTX-class GPU)

| quality | size | spp | frames | time |
|---|---|---|---|---|
| preview | 480×270 | 8 | every 6th | ~1 min |
| draft | 960×540 | 24 | all 270 | ~50 min |
| final | 1920×1080 | 96 | all 270 | several hours on CPU; ~15–20 min on a fast GPU |

On CPU, deliver the draft and offer the final as a background job or GPU run.

## Adapting the template

- **New character**: replace `make_character()`; keep the root (feet origin, carries squash) + rig split.
- **New UI**: rewrite ui.html panels/buttons; keep `render(t)`, `layout()`, data attributes.
- **New story**: edit HOPS / event beats; add UI reactions inside `render(t)` keyed off `pressT(name)`.
- **No character**: drop HOPS, animate slabs/camera only; check.py framing checks need a subject,
  so point `screen_track` at the hero object.
- Files in the template: `timeline.py`, `ui.html`, `render_ui.py`, `scene.py`, `render.py`,
  `sound.py`, `check.py`, `film.sh`.
